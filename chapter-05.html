Skill의 구조와 적재 방식

.claude/skills/add-rule/  ·  폴더 이름이 명령 이름
add-rule/
├── SKILL.md              절차와 규약

# SKILL.md
name: add-rule
description: 규칙 코드를 받아 구현, 테스트, 등록까지 처리합니다.
  규칙을 추가할 때 사용합니다.
  • 적재되는 시점: 평소에는 name 과 description 만 올라가 있습니다. 본문은 부를 때 실리고, 한 번 실리면 그 세션 동안 남습니다.
  • description 의 역할: 모델은 이 한 줄만 보고 Skill을 부를지 정합니다. 무엇을 하는지와 언제 쓰는지를 함께 적습니다.
  • 함께 두는 파일: 스크립트와 참조 문서를 폴더에 같이 넣고 본문에서 ${CLAUDE_SKILL_DIR} 로 가리킵니다. 같은 경로를 allowed-tools 에도 적어 두면 실행할 때 승인을 묻지 않습니다.

실습 2 · 규칙 추가 Skill 만들기

  1. /context 로 현재 프로젝트 메모리 적재량 확인
  2. 요청: CLAUDE.md 의 규칙 추가 절차를 add-rule Skill로 옮겨 줘. 규칙 코드를 받아 구현, 테스트, 등록까지 하고 규정 문서도 Skill 안에서 참조하게 해 줘
  3. 요청: 규칙 구현 파일, 테스트, 픽스처, 앱 컨테이너 등록, 테스트 컨테이너 등록 다섯 곳에 규칙 하나가 모두 반영됐는지 확인하는 스크립트를 scripts/check_rule.py 로 Skill 폴더에 만들고, 절차에서 ${CLAUDE_SKILL_DIR} 경로로 호출하게 하고 allowed-tools 에도 등록해 줘
  4. SKILL.md 를 열어 절차의 실행 명령이 uv run 인지 확인. ${CLAUDE_SKILL_DIR} 를 실제 경로로 바꾸지 말라는 지시 문장이 없으면 직접 추가
  5. uv run python .claude/skills/add-rule/scripts/check_rule.py R010 실행. 이미 만든 규칙으로 동작 확인
  6. /context 를 다시 실행해 Skills 항목에 add-rule 이 올라왔는지 확인
절차가 사라진 것이 아니라 부를 때만 컨텍스트에 오르도록 자리를 옮긴 것입니다.
규칙을 만들지 않는 요청에서는 이제 이 절차와 경비규정 전문이 올라가지 않습니다.

Subagent

컨텍스트를 나누는 Subagent

  • Subagent: 시스템 프롬프트와 도구 목록을 따로 지정하는 Agent입니다. 자체 컨텍스트 창에서 실행되고 마지막 응답만 돌려줍니다.
  • 따로 맡기는 일: 파일을 여러 개 읽어야 하는 조사, 같은 대상을 다른 시선으로 보는 검토, 권한을 제한해야 하는 실행입니다. 중간 과정이 길고 결과만 필요하다는 공통점이 있습니다.
  • 이 챕터에서 맡길 일: 규정과 구현의 대조입니다. 규칙 일곱 개를 만든 대화에서 그대로 이어 검토하면 모델은 규정이 아니라 앞서 스스로 내린 판단을 다시 읽습니다. 그래서 잘못된 결과물도 맞다고 판단하고 넘어가기 쉽습니다.
Subagent는 이 대화와 분리된 자리에서 실행됩니다.
컨텍스트: 지금까지의 대화가 넘어가지 않고 중간 과정도 돌아오지 않습니다.
지시: 전달한 내용만 수행합니다.
권한: 허용한 도구 외에는 사용할 수 없습니다.
