픽스처 작성 기준

픽스처는 규칙 하나를 검증하는 최소 데이터입니다. 아래 다섯 가지를 기준으로 행을 구성합니다.
기준내용
대상 규칙 한정다른 규칙의 위반이 섞이지 않도록 나머지 열을 조정

앞 챕터에서 만든 골든 세트 두 개(base, set-2)에는 R021 위반이 한 건도 없습니다. 규칙을 추가한 뒤 base 나 set-2 가 깨졌다면 픽스처가 아니라 구현이 규정과 다른 것입니다.

집계는 판정이 끝난 결과를 부서 같은 기준으로 묶어 표로 만드는 계산입니다. 규칙이 청구를 한 건씩 판정하는 것과 달리, 집계는 판정 결과 전체를 대상으로 합니다. 아래 표는 규칙과 집계를 하나씩 추가할 때의 수정 지점을 비교합니다.
규칙집계
추가 파일규칙 파일 1개집계 파일 1개
연동 수정 지점container.py 2개: 앱 · 테스트container.py 1개: 앱
출력 계층수정 불필요: 위반 객체가 규칙 이름을 함께 전달수정이 필요 없는 구조 설계가 실습 과제
출력이 집계 종류를 모르게 만들면 집계를 추가해도 출력을 고칠 일이 없습니다.
리포터는 집계 목록을 순서대로 출력할 뿐이므로, 집계 추가는 목록에 항목 하나를 더하는 작업으로 끝납니다.

집계

집계에서 판단이 필요한 지점

  • 금액이 비었거나 음수인 건: R002 위반으로 이미 반려된 건입니다. 금액 합계에 어떻게 반영할지 정합니다.
  • 반올림이 일어나는 지점: 계산 계층에서 한 번만 합니다. 표현 계층이 다시 반올림하면 터미널과 웹의 숫자가 달라집니다.
  • 청구가 없는 부서: 표에 넣지 않습니다. 판정 결과에 없는 부서를 어디선가 가져와야 한다면 계층을 넘은 것입니다.
요청에 함께 붙여 넣을 세 줄
집계 처리 기준
1. 금액이 비어 있는 건은 합계에서 0으로 본다. 반려금액에는 그 건의 금액을 그대로 넣는다.
2. 반올림은 계산 계층에서 한 번만 한다. 표현 계층은 다시 계산하지 않는다.
3. 청구가 한 건도 없는 부서는 표에 넣지 않는다. 반려율 내림차순으로 정렬한다.
세 항목을 적지 않으면 모델이 임의로 정합니다.
어느 쪽으로 정해도 결과는 그럴듯해 보이므로, 정한 내용을 요청에 함께 실어야 결과가 같은 형태로 나옵니다.

실습 4

실습 4 · 부서별 집계

  1. 요청: 판정 결과를 부서별로 묶는 집계를 추가해 줘. 추상 클래스는 Aggregator, 구현은 DepartmentAggregator, 결과 표는 AggregationTable 로 만들고, SettlementResult 의 aggregations 에 담아 줘 (앞 슬라이드의 집계 명세와 집계 처리 기준 세 줄을 함께 붙여 넣어 전달)
  2. 요청: ConsoleReporter 가 집계 종류에 의존하지 않고 aggregations 를 순서대로 표로 출력하게 해 줘
  3. 요청: 파일을 읽지 말고 판정 객체를 테스트 코드에서 직접 구성해 넘기는 집계 테스트를 만들어 줘
  4. uv run pytest 로 골든이 그대로 통과하는지 확인합니다
  5. uv run settle tests\golden\base\input.csv 로 다섯 부서가 한 표에 나오는지 확인합니다
골든 테스트는 judgements 만 비교합니다.
결과 객체에 집계가 추가되어도 기대 출력은 달라지지 않습니다. 여기서 골든이 깨졌다면 집계가 판정을 바꾼 것입니다.
같은 절차를 반복하게 되면 파일로 옮깁니다.
집계를 하나 더 붙일 때마다 이 요청을 다시 쓰게 됩니다. CLAUDE.md 나 Skill에 절차를 적어 두면 다음부터는 집계 이름만 넘기면 됩니다.

사람이 판단하는 지점

  • 푸시 없이 커밋까지: 챕터 6에서 git push 를 deny 에 넣었고, 실습 저장소는 읽기 전용이므로 푸시 권한도 없습니다.
